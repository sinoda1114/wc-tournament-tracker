# 商用サービス化レビュー（2026-06-05）

WC Tournament Tracker を「個人プロジェクト」から「商用サービス」へ引き上げるための網羅調査。
サービス機能（プロダクト）とシステム機能（非機能要件）を分け、マクロ（戦略）×ミクロ（具体）、
水平（領域網羅）×垂直（重点深掘り）で整理する。

---

## 0. 現状サマリ（2026-06-05 時点）

**あるもの**
- 公開: 決勝Tブラケット/カード、グループリーグ+順位表、試合詳細+会場情報、出場国(大陸別)、
  スカッド(選手/監督)、優勝予想(`prediction`, `crowd_votes`)、お気に入り(localStorage)、日付フィルター
- 管理: 単一パスワード認証、試合結果入力→`bracket_edges`伝播
- 基盤: Next 15.3.3 (App Router) / Turso(libSQL)生SQL / Mantine / Vitest 134件 / マイグレーション0001-0007

**商用化に向けて「無い」もの（重要なギャップ）**
- 認証/認可: 平文パスワードCookie1個のみ（Clerk導入は予定）。ロール無し、監査無し
- データ供給: **試合結果が管理画面の手入力のみ**（自動取込なし）
- 信頼性の足回り: `error.tsx`/`loading.tsx`/`not-found.tsx`/`global-error.tsx` 無し、`middleware.ts` 無し
- 集客基盤: `sitemap.ts`/`robots.ts`/OGP画像/`manifest.ts`(PWA) 無し
- 品質ゲート: CI/CD 無し（`.github/workflows` 無し）
- 入力検証: zod等のスキーマ検証 無し（Server Actionは型のみ）
- 観測性: Sentry/ログ/アナリティクス/Web Vitals/アップタイム監視 無し
- 国際化: 日本語ハードコード（i18n基盤無し）
- 法務: 利用規約/プライバシー/Cookie同意/特商法表記/**FIFA知財の整理** 無し

## 1. マクロ × 水平：全体マップ（領域の網羅）

### A. プロダクト戦略（先に決めるべき土台）
1. **収益モデル**: 広告 / アフィリエイト(放送・配信・チケット・物販) / サブスク(広告除去・高度予想) / データAPI提供 のどれを主軸にするか。これで非機能の重み（決済・課金基盤の要否）が変わる。
2. **ターゲット**: ①日本のファン中心 ②訪日客(多言語) ③グローバル。→ i18n/コンテンツ/法域(GDPR等)の判断が変わる。
3. **大会後の継続性**: WC2026限定で畳むか、EURO/コパ/クラブW杯/各国リーグへ横展開するか。→ DBスキーマを「大会一般」へ一般化するか(現状は2026前提のハードコードが各所にある: `BracketLayout`のmatch ID配列、R32スロット文字列)。
4. **データ供給戦略**: 手入力は本番104試合+72グループ戦で**破綻する**（後述 垂直V1）。外部スポーツデータAPI契約が事実上の前提。

### B. サービス機能（ユーザー目線・水平リスト）
- アカウント＆**お気に入りのクラウド同期**（localStorage→DB、デバイス間共有）
- **予想ゲーミフィケーション**（`crowd_votes`を核に: 勝敗ブラケット予想・スコア予想・ポイント/ランキング・ミニリーグ・バッジ）
- **通知/リマインダー**（試合開始前・お気に入り国の試合・Webプッシュ・カレンダー`.ics`連携）
- **ライブ**（リアルタイムスコア・ゴール速報・自動進行・「試合中」バッジの自動化）
- **視聴導線**（日本の放送/配信リンク=ABEMA/NHK等、チケット/旅行アフィリエイト→収益）
- **コンテンツ**（試合プレビュー/レビュー、得点/アシストランキング、選手スタッツ、H2H対戦成績、グループ突破確率、3位通過の組合せ可視化）
- **シェア**（動的OGP画像でブラケット/予想を共有、SNS連携）
- 検索強化、**PWA/オフライン**、ライト/ダーク切替(現状dark固定)、データ可視化(順位表の突破ライン)

### C. システム機能（非機能要件・水平リスト）
- **認証/認可**: Clerk + ロール(admin/editor/user)、Server Action全認可、`middleware`でルート保護、監査ログ
- **セキュリティ**: セキュリティヘッダ(CSP/HSTS/X-Frame)、レート制限(特にadmin login総当たり)、zod入力検証、シークレット管理、**Next 15.3.3 既知CVE→パッチ**、`npm audit`+Dependabot(グローバル方針に合致)
- **可用性/信頼性**: Tursoバックアップ/embedded replica、`error/loading/not-found`、ヘルスチェック、グレースフルデグレード(DB障害時UI)
- **パフォーマンス**: 全ページ`force-dynamic`の見直し→ISR/`revalidateTag`、`next/image`、CDN、bundle分析
- **観測性**: Sentry(エラー)、構造化ログ、Web Vitals、アクセス解析、アップタイム監視
- **CI/CD**: typecheck/lint/test/build/audit自動化、プレビュー環境、自動デプロイ
- **データ整合性**: マイグレーション運用(整備済み)、**バックアップ/リストア演習**、seed冪等性(良好)
- **国際化/アクセシビリティ/SEO**: i18n基盤、WCAG2.2、構造化データ/メタ/OGP

### D. 法務・コンプライアンス（商用では非営利より厳格）
- **FIFA知財**: 「FIFA」「FIFA World Cup」「World Cup」エンブレム/公式マークは厳重に保護。非公式ファンサイトは「FIFA非公認」明記・ロゴ不使用・公式名称の商標的使用回避が必須。**課金/広告収益があると更に厳しい**。
- **会場/選手データの権利**: スタジアム通称(SoFi等)はスポンサー商標。選手名/写真/スタッツは提供元のライセンス次第。データAPIの商用利用条項を要確認。
- **個人情報/規約**: 利用規約・プライバシーポリシー・Cookie/localStorage同意・(課金時)特定商取引法表記・(EU向けなら)GDPR。

## 2. ミクロ × 垂直：重点領域の深掘り

### V1. データ自動取込（最大の事業リスク）
- 現状: `admin/matches/[id]`で人手入力→`updateMatchResult`→`propagateMatchResult`。本番は約32試合/日のピーク。**人力では即時性・正確性が破綻**。
- 提案: スポーツデータAPI(API-Football / Sportradar / Football-Data.org 等)連携。
  - 取込ワーカー(cron/edge)で結果をポーリング→`updateMatchResult`を再利用して伝播。手入力は「上書き/訂正」用に残す。
  - ライブはAPIのライブエンドポイント or Webhookで分単位更新。
  - コスト: 公式に近いほど高額。MVPは安価API+遅延許容、ローンチで上位プランへ。
- 影響: `home_team_id`等の確定ロジック、R32の3位通過割当(現在手動/NULL)を自動確定する仕組みが要る。

### V2. 認証・認可・お気に入り同期
- 現状: `lib/auth.ts`が`ADMIN_PASSWORD`平文をCookieに保存(HANDOFF既知の弱点)。`updateAdminMatchAction`は認可チェックあり。
- 提案: Clerk導入時に
  - ロール(admin/editor/viewer)を`publicMetadata`で持ち、`middleware.ts`で`/admin/*`保護、Server Action先頭で再認可。
  - **お気に入りをDB化**（`user_favorites(user_id, fifa_code)`）。`useFavoriteTeams`をAPI同期に拡張、未ログインはlocalStorage→ログインで自動マージ。
  - 予想(`crowd_votes`)を匿名→ユーザー紐付けに(なりすまし/多重投票対策)。

### V3. ライブ/リアルタイム
- 現状: `export const dynamic = 'force-dynamic'`で都度フェッチ。Server Action後`revalidatePath`。リアルタイム更新は無し。
- 提案: 試合中ページはSSE/ポーリング(短間隔ISR)で自動更新。ゴール時Webプッシュ。`status='in_progress'`の自動制御(キックオフ時刻起点)。

### V4. SEO / OGP / シェア（集客の生命線）
- 現状: ルート`metadata`のみ。`sitemap`/`robots`/動的OGP/構造化データ無し。全ページ`force-dynamic`はSEOに不利。
- 提案: `sitemap.ts`(全試合/国/グループ)、`robots.ts`、各試合/国の動的OGP画像(`opengraph-image.tsx`)、`SportsEvent`/`BreadcrumbList`構造化データ、静的化可能ページのISR化。`seo`スキルが使える。

### V5. 信頼性の足回り（今すぐ効く低コスト改善）
- `app/error.tsx`・`global-error.tsx`・`loading.tsx`・`not-found.tsx`(現状`notFound()`の着地が素)を追加。
- DB障害時のフォールバックUI（`getDb`が例外→500そのまま）。
- CI: typecheck+lint+test+`npm audit --audit-level=high`(グローバル方針)、Dependabot、プレビュー環境。
- 観測性: Sentry + Web Vitals。環境変数の起動時バリデーション(現状`TURSO_DATABASE_URL`欠落でランタイム例外)。

### V6. 法務（着手前に確認すべき）
- FIFA知財の線引き（非公認明記/ロゴ不使用/名称の使い方）。
- データ/画像のライセンス条項（商用可否）。
- 課金するなら特商法表記・決済(Stripe)・サブスク基盤。

## 4. フェーズ別ロードマップ（叩き台）

- **Phase 0 商用化の前提固め**: 収益/ターゲット/大会後方針の決定、FIFA知財確認、データAPI選定。
- **Phase 1 ローンチ最低ライン**: Clerk認証+RBAC、お気に入りDB同期、error/loading/not-found、CI+監視、Next CVE対応、規約/プライバシー、sitemap/OGP。
- **Phase 2 集客と回遊**: データ自動取込、SEO本格化、予想ゲーミフィケーション、通知/視聴導線。
- **Phase 3 グロース**: ライブ更新、課金、i18n、他大会展開(スキーマ一般化)。
