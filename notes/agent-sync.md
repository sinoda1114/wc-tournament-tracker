# エージェント同期プロトコル（番人 ⇄ 実装エージェント）

> **目的: 人間(ユーザー)を伝書鳩にしない。** 番人と実装エージェントは別セッションで直接会話できないが、
> **共有アーティファクト経由で自律同期する**。ユーザーが毎回「PR #N をマージして」と中継しなくても回る状態を保つ。
> これが正本。全エージェントは起動時にこの規約に従う（[[task-ledger-location]] / `CLAUDE.md` と一体）。

## 同期メディア（人間を介さない共有チャネル）

1. **GitHub PR（`gh pr list --state open`）** = 作業キュー＆PR状態の正本。
2. **タスク台帳（`notes/task-ledger.md`）** = タスク内容・優先順位（🎯）・完了の正本。
3. **本ファイルの「📨 受け渡しボード」** = PR に乗らない非同期の申し送りメモ。

## "待たない" 原則（各自の責務）

### 実装エージェント
- 台帳の 🎯 優先順位から着手 → worktree → 2段ゲート → push → PR。
- **PR を出したら、本ファイルの受け渡しボードに1行追記**：`- [ ] PR #N <概要> → マージ依頼（YYYY-MM-DD HH:MM）`。
  ＝ 番人がユーザー経由でなく拾える。
- 番人の完了は **台帳の ✅完了 / `gh pr list`** で確認（ユーザーに聞かない）。
- DB マイグレーション/外部影響を含む PR は、ボードに **⚠️DB** 等の注記を付ける。

### 番人（デプロイ担当）
- **呼ばれたら（用件が何であれ）まず `gh pr list --state open` と本ファイルのボードを確認**。
  マージ依頼済みの open PR は、点検（競合/DB/依存）→ マージ → **台帳を完了同期** → ボードに `✅ #N マージ済み` を返信。
- **ユーザーに PR 番号を教えてもらうのを待たない**（open PR は自分で見つける）。
- 本番 DB 変更・外部公開など**ユーザー許可が要るものだけ**ユーザーに確認。
- マージ後は必ず `gh pr list --state open` の残数を報告。

### ⚠️ デプロイ取りこぼし防止（2026-06-12 の #35 事故の教訓）

Vercel の git 自動デプロイは、**短時間に複数コミットが main へ来ると 1 本デプロイを取りこぼす**ことがある（#33→#34→#35 を立て続けにマージ→#35 の本番ビルドが発火せず prod が古いまま、が発生）。コード/PR/マージは正常でも本番未反映になるため、番人は必ず:

1. **連続マージしない**: 1 本マージしたら **`vercel ls` でそのマージの Production デプロイが Ready** になるのを確認してから、次の PR をマージする（間隔を空ける）。
2. **マージ後にデプロイ発火を確認**: `vercel ls` の最新 Production が「今マージしたコミット」か照合。**発火してなければ自動デプロイ漏れ** → 番人が**統制デプロイで補う**（`git worktree add /tmp/x origin/main` → そこで `vercel link --yes --project wc-tournament-tracker` → `vercel --prod --yes` → 撤去）。本番が最新 main と一致するまで見届ける。
3. 手動 `vercel --prod` は本来禁止だが、**この「自動デプロイ漏れの補填」は番人の正当な例外**。実施したら一言記録する。

## 衝突回避
- 1エージェント＝1 worktree＝1ブランチ。main 直 push 禁止・PR マージは番人のみ（[[dev-workflow-multiagent]]）。
- 台帳・本ファイルは**短い差分で**更新し、編集が衝突したら最新を取り込んでから再編集。
